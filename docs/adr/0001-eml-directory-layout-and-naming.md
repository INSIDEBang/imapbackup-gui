# 0001 - eml 输出采用"文件夹嵌套 + 月度分组 + 主题优先文件名"

Status: accepted

eml 输出把每个邮箱文件夹映射为 `<eml-dir>/<文件夹各段>/<yyyy-MM>/` 下的独立 `.eml` 文件，文件名为 `<消毒主题>_<消毒Message-Id>_yyyyMMdd.eml`，重名追加 `（n）`。选这个布局是因为公司用户需要按时间与主题直接浏览、筛选邮件文件，mbox 的"点平铺单文件"无法满足。分桶时间优先取服务器 INTERNALDATE（归一到本机时区），回退 `Date:` 头、下载时刻。

## Considered Options

- 仅 `<Message-Id>.eml` 命名：最稳定但对人不友好，被"主题在前、可读性优先"的需求否决；Message-Id 段仍保留在文件名中兜底唯一性。
- 用 `Date:` 头分桶：发件人撰写时间会因离线撰写/延迟投递失真，故只作 INTERNALDATE 的回退。
- 解析文件名做增量判重：主题/日期/`（n）` 后缀使文件名存在歧义，且上游 `scan_file` 本就是读 mbox **内容**判重——eml 侧同样读文件头部提取 Message-Id，使命名方案与增量正确性解耦（将来改命名不破坏既有备份的增量）。

## Consequences

- 布局一旦存在存量备份即难以更改（用户按此结构归档），后续调整需带迁移方案。
- 对缺失 Message-Id 的消息，写入 eml 时会注入一行合成 `Message-Id` 头（与上游 mbox 输出行为一致）——这是"eml 保存原始字节"的唯一例外，否则内容级判重无法识别这类消息。
- Windows 文件系统大小写不敏感：判重集合键虽大小写敏感（与上游一致），但写入前的 `.exists()` 检查天然覆盖大小写冲突，全同名文件靠 `（n）` 后缀兜底。
- 完整路径预算 240 字符内（主题 60、超长 Message-Id 截断加哈希后缀），防 MAX_PATH 超限。
