# 0004 - 双格式备份按格式独立判重

Status: accepted

当 mbox 与 eml 两种输出都勾选时，"待备份"按格式独立计算：一封消息**只要某个已选格式缺它就属于待备份**，下载一次后只写入还缺它的那个格式。取代 ADR-0003 结尾"增量判重取 mbox 与 eml 已扫描消息的**并集**"（已 superseded）。

起因是真实使用中的故障：用户先长期只勾 eml、已把某账号全部邮件备份为 `.eml`，随后补勾 mbox。并集判重下这些消息已被 eml 扫描计入"本地已有"，待备份数为 0，界面报"已是最新，无待备份邮件"，mbox 一封也没有被写入——用户以为备份已完成，实际缺了整整一种格式。

并集语义把两种输出当成"同一种备份的两个副本、有一个就够"，但两者是用户各自要保留的输出，各自有独立的完整性。用户要问的是"mbox 里有这封吗"，不是"任意一份里有吗"。

实现：`main()` 与 GUI 的 `_backup_worker` 不再把 `scan_file` 与 `scan_eml_dir` 的结果 `update` 进同一个 dict，而是分别保存；只把**已选**格式的结果放进 `selected`，`any(mid not in local for local in selected)` 决定待备份；`download_messages` 新增 `skip_mbox` / `skip_eml`（默认为 None，保持单格式与 CLI 现状不变），逐封循环里对两个输出各自加 `msg_id not in skip_*` 门控。

## Considered Options

- **并集判重 + 只改提示文案**（ADR-0003 的原有选择）：用户点备份仍拿不到 mbox 数据，且文案会声称 mbox 已存在。否决。
- **mbox 与 eml 勾选互斥**：直接砍掉"两种都要"的能力，而迁移期间双份留底是常见诉求。否决。
- **调两次 `download_messages`**（第一次只带 mbox 缺集且 `eml_dir=None`，第二次反之），核心签名不动：两个格式都缺的消息会被 `BODY.PEEK` 抓两遍；GUI 的"已备份 N 封"会重复计数；每个文件夹要重新 `SELECT` 两次。否决。

## Consequences

- 修复后第一次双格式运行是一次完整重下载（只补缺的格式）：本地没有另一格式副本，只能从服务器取。之后恢复增量。不做本地格式间互导——mbox 里的消息字节已被前缀逃逸处理过，eml 保存的是原始字节，反向还原不可靠。
- "本次备份 N 封"按消息计数，不按写盘次数：一封信只补了 mbox（eml 本就有）仍记 1 封，进度分母"待备份 X 封"与之一致。
- 每封消息只 fetch 一次，单格式路径与 CLI 终端输出逐字节不变（`skip_*` 默认 None）。
- 未选格式不参与判重，因此不会让每封都显示成待备份；`overwrite=True` 时两个扫描都返回空 dict，所有消息算待备份，与上游"覆盖即重下"一致。
- 判重正确性仍依赖既有约定：写入时会为缺 Message-Id 的消息注入合成标识，因此内容级扫描在 mbox 与 eml 两侧读到的是同一个键（见 ADR-0001）。
