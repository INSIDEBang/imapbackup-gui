# 0009 - 关闭窗口后的后台驻留与托盘契约（关闭三态偏好 + 纯标准库托盘）

Status: accepted

在此之前，点窗口关闭按钮就是进程退出：备份线程是 daemon，`root.destroy()` 会把它连同 socket 一起掐掉；运行中唯一的一道护栏是「备份正在进行中，确定要退出吗？」弹窗。用户诉求是「关闭窗口也能在后台默默备份，点任务栏图标再显示出来」。

决定：

- **托盘宿主用纯标准库实现**（`imapbackup_tray.py`）：ctypes 直接调 `Shell_NotifyIconW`，自建隐藏消息窗口 + 专属消息循环线程。不用 pystray/Pillow——运行时代码的标准库约束优先，且少两个依赖就少一层打包与杀软面。托盘回调不挂 Tk 窗口：那要子类化 Tk 的窗口过程、依赖 Tcl 内部的消息派发。
- **线程边界照旧**：托盘线程绝不碰 Tk 与界面状态，托盘回调只往 GUI 事件队列投元组（`tray_show` / `tray_stop` / `tray_quit`），由既有 `_pump` 在 Tk 线程消费；界面侧所有托盘操作（挂图标、气泡、改 tooltip、收图标）经命令队列 + `PostMessageW(WM_APP+3)` 转给托盘线程同步执行，`show()` 返回是否挂出成功。
- **关闭行为偏好三态**：`ask`（每次询问，默认）/ `tray`（隐藏到后台）/ `exit`（退出程序），存在既有界面设置文件的新键 `close_action`（**不升 `UI_SETTINGS_VERSION`**：`_read_ui_settings` 对版本不符是整份丢弃，升版本会让老用户的列宽/窗口/账号配置一起失效；新键按字段独立校验，非法值回退 `ask` 并记 warning，同 ADR 0008 的降级口径）。询问对话框两个按钮 + 「记住我的选择」复选框：勾了才写偏好，不勾只作用于本次。
- **关闭动作由纯函数决定**：`decide_close(preference, hidden=)` → `force_exit` / `hide` / `exit` / `ask`。是否运行中不参与判定，它只改变对话框文案与托盘「退出」的二次确认。
- **「已隐藏」以 `root.state() == "withdrawn"` 为唯一事实来源**（不另设影子标志），并由此定下一条硬规则：**窗口已隐藏时收到的关闭请求一律真退出**。隐藏窗口没有任务栏按钮，能对它发 WM_CLOSE 的只有外部程序（安装器、卸载器的 CloseApplications、任务管理器），把这类请求解释成「再藏一次」会让升级/卸载关不掉旧实例。
- **托盘不可用时退化为最小化到任务栏**（非 Windows，或窗口/图标建不出来）：出口路径必须先成立，再谈隐藏。
- **图标随程序启动常驻**（窗口可见时也挂着），直到退出才由 `close()` 收掉：它是「程序还在跑」的常驻标记，也让右键菜单（显示 / 停止 / 退出）随时可达。tooltip 与菜单「停止备份」的可用性随运行状态经 `_sync_tray()` 追平；隐藏窗口前会再 `show()` 一次并以其结果为准——拿不到就退化为最小化到任务栏。explorer 重启靠 `TaskbarCreated` 广播重建图标。
- **后台期间备份结束只弹托盘气泡**，窗口保持隐藏（完成给「本次备份 N 封，跳过 M 封」、停止、失败三种文案）；点气泡或左键点图标恢复窗口。选它而不是自动弹回窗口，是不打扰优先——用户已经明确选择了「隐藏」，结果留给气泡，需要细节时再打开。
- **二次启动唤起已有实例**：单实例互斥量保持原样（也继续与安装器 `AppMutex` 逐字一致），第二个进程在判定已有实例后，用 `FindWindowW(托盘窗口类名)` + `PostMessageW(WM_APP+2)` 请它把主窗口显示出来，成功返回 0。GUI exe 是 `console=False`，原来那句「已经在运行了」用户根本看不到。
- **设置落盘时机不变**（ADR 0008 的单一写入路径）：设置页与关闭对话框只改内存，隐藏/退出/外部关闭三条路径各调一次 `_save_column_config()`；隐藏时先落盘再 `withdraw()`，此刻窗口还可见，正常几何与最大化状态读得对。
- **页面外壳与导航**：顶部 tk 原生菜单栏「备份」「设置」两项直接切页（radiobutton 顶层项，当前页带选中点，不做下拉、不开新窗口）；设置页按主流应用做成两栏——左分类栏（`tk.Listbox`，白底 + groove 外框，固定 160px）+ 右详情区（`tkraise` 切分类），分类由 `SETTINGS_SECTIONS` 表驱动，加分类＝加一行 + 建一个详情 Frame。v1 只有一个分类「窗口与后台」。
- **菜单栏的客户区代价已补偿**：Windows 原生菜单栏在窗口真正落地前会把几何高度吃掉一截（真机实测默认 736 落地成 716 客户区），因此 `__init__` 末尾先 `update()` 让窗口落地、再重设一次目标几何字符串；最大化状态在构造早期已恢复，此时不再重设（ADR 0008 要求先正常几何再最大化）。

## Considered Options

- **关闭即最小化到任务栏**（零 Win32 代码）：任务栏按钮一直可见，实现与测试最简；但不符合「默默备份」，且运行中再次关闭没有自然出口。否决，改为托盘 + 托盘菜单。
- **只在备份运行中才允许隐藏**：能防常驻进程被遗忘；但用户要的是可记住的三态偏好（对齐主流应用），而不是按运行状态自动切换。否决。
- **托盘图标只在窗口隐藏时挂着**（窗口恢复即 `NIM_DELETE`）：出口更“干净”，但用户看不出程序还在跑、菜单也不是随时可达，且没有任务栏按钮时无从判断实例状态。用户复核时否决，改为常驻（图标随启动挂出、只在退出时移除）。
- **pystray + Pillow**：代码更短，但新增两个运行时依赖，PyInstaller 打包与杀软面变大，且需单独批准。否决（AGENTS.md 的标准库约束）。
- **备份结束自动把窗口弹回来**：结果第一时间可见，但打断用户当前正在做的事，也与「隐藏到后台」的语义相反。否决，改气泡。
- **（接受的代价）**① 托盘代码是首次引入 Win32 消息循环，`TaskbarCreated`、菜单前景修正、图标句柄释放三处是已知坑点，全部 try/except + 记日志，任何托盘异常都不得让备份停摆（退化为 iconify）；② 窗口可见且偏好=隐藏时，安装器发来的 WM_CLOSE 会走对话框/偏好而不是立即退出，极端情况下可能关不干净（`force_exit` 规则只覆盖隐藏状态）；③ 隐藏期间邮件列表与运行日志照常刷新，内存/CPU 与可见时一致，不做额外优化。

## Consequences

- 人工验收（安装包，按 ADR 0007 口径）：启动后托盘图标即在（窗口可见时也在），右键菜单可用；运行中关闭 → 对话框；选「隐藏到后台」并记住 → 窗口消失、备份继续；跑完只弹气泡、窗口保持隐藏；点托盘图标恢复窗口后图标仍在。设置页改回「每次询问」→ 下次关闭重新询问；隐藏期间双击快捷方式 → 已有窗口被唤起并置前；安装器/卸载器在实例隐藏时仍能关掉程序；explorer 重启后图标自动重建；注销/关机不被隐藏窗口阻塞；非 Windows 源码运行退化为最小化。ctypes 接线另有回归 `test_gui_background.py::test_tray_host_wiring_is_available_on_windows`（真造宿主、挂图标、走通唤起通道），但图标外观与菜单仍以真机人工验收为准。
- 注销/关机不保护正在运行的备份：进程被系统结束与今日行为一致，增量备份随时可重跑，不在此条约束内。
- 互斥量名、安装器 `AppMutex`、CLI、版本号（1.6.0）均未改动；`docs/agents/gui.md` 增加「后台驻留、托盘与页面导航」一节作为后续修改的约束入口。
