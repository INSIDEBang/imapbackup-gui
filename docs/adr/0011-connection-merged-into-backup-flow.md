# 0011 - 连接并入备份流程（预检串行 + 并发下载）

Status: accepted（连接预检串行 + 密码补录仍有效；并发运行编排部分被 ADR 0012 取代——账户改为各自独立运行、可追加、独立停止）

「连接」不再是用户可见的独立动作：移除备份页的「⇄ 连接并加载文件夹」按钮与整套连接状态机（`connect_state`、连接 spinner、连接提示行、stale 过期概念）。文件夹清单改为静默按需加载——打开应用、切换账户、保存账户后各触发一次（同一账户去重、连接参数没变则不重拉），失败只写日志、不打断用户。真正的连接推迟到备份时：点「开始备份 / 备份所选」先弹**连接预检弹窗**，按账户顺序串行检测（登录 + LIST + 登出），全部通过后弹窗自动关闭、通过的账户**并发同步**（每账户一条下载线程、独立 IMAP 连接）。密码错误（认证失败）弹**密码补录窗**（重试 / 跳过该账户，带「保存密码」复选框）；关闭预检弹窗 = 终止本次备份。运行日志并发混排、每行带账户名前缀；邮件列表只显示当前选中账户的邮件，切账户即换视图。

连接参数快照仍是「文件夹清单是否过期」的判据（沿用 ADR 0010），但不再驱动任何按钮态——过期只意味着下次静默加载会重拉。判重不变量不受并发影响（每账户独立判重、每封消息只 fetch 一次，见 ADR 0004）。

## Considered Options

- **保留手动连接按钮 + 周期性自动检测 + 账户状态图标**：状态最实时，但用户明确要求去掉连接动作、连接只在备份时做，且周期检测会反复登录服务器、状态图标与刷新按钮都属多余；放弃。
- **可恢复的暂停（关闭预检弹窗记住断点、下次续跑）**：体验最好，但要为每个账户持久化下载断点、增量续传边界复杂；用户确认「关闭 = 终止」，放弃。
- **预检继续串行下载（沿用旧批量顺序）**：实现最省事，但用户要求全部检测通过后并发同步；改并发（每账户一线程），放弃。
- **连接失败一律弹框中断**：简单，但密码错误会让多账户批量卡在第一个错账户；改为密码错误弹补录窗、其余失败标在行内并继续检测后面的账户，放弃。
- **密码补录窗强制保存**：少一步选择，但把用户没让存的密码写进磁盘不对；带「保存密码」复选框（默认勾选），不勾则只在本次运行生效，放弃前者。

## Consequences

- 备份页「账户信息」卡变纯只读展示（原按钮行整行删除）；`connect_state`、`STALE_HINT_TEXT`、连接 spinner、`_apply_connect_state`/`_refresh_stale`/`_show_conn_hint` 等全部移除。
- 预检弹窗逐行显示每个账户的检测状态（等待 / 连接中 / 成功 / 失败原因 / 已跳过）；关闭弹窗或点「终止备份」= 终止本次备份，已检测与未检测账户全部取消。
- 密码补录窗（模态）：输对密码重试该账户（勾选保存则写入 `password_dpapi` 并落盘，不勾选只进本次运行快照 `_run_passwords`）；跳过 / 关窗则略过该账户继续检测其余。
- 并发同步：每个通过预检的账户一条下载线程，各持独立 IMAP 连接；单账户失败只记该账户，全部收尾后汇总 `batch_done`。停止（按钮/托盘）经全局 `stop_flag` 对所有线程生效。
- 运行日志经「每账户一个真实 Logger + 前缀 Filter」（`_account_logger`）加 `[账户名] ` 前缀，混排但每行可辨；core 的接口只收 `logging.Logger`，故不用 LoggerAdapter。
- 邮件列表按选中账户过滤（数据本就按账户分槽存于 `state["messages"]`）：并发下载时各账户各存各的，切账户即换视图；进度条跟随当前选中账户。
- 静默加载与预检共用 `core.connect_and_login` + `core.get_names` + 登出这条链路，但事件分叉：静默走 `folders_loaded`/`folder_load_failed`（只写日志），预检走 `preflight_result`（驱动弹窗）。
