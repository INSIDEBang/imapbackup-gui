# 0007 - 卸载改为向导式交互（UninstallString 改写 + /NOSTYLE 标记）

Status: accepted

「是否删除运行日志」的卸载交互是第四版：usUninstall 弹窗询问 → 进度窗体页脚复选框 → 自定义选项窗体两段式 → 本条的向导式三段流。前三版都活在「Inno 原生卸载器只有确认弹窗＋进度窗＋完成弹窗」的框里，本版第一次把交互整体接管。

动因（真机验收连续两次否决）：页脚复选框在进度自动跑完前根本来不及交互（第二版证伪）；两段式修复了时机，但「向导首页 →『您确认要完全移除…吗？』→ 进度 →『已顺利移除』」仍双确认、三个界面观感割裂（第三版被否）。用户给出对标：AutoClaw（NSIS 向导）的「欢迎页（可带选项）→ 进度页 → 完成页」。

决定：

- **UninstallString 改写**：`CurStepChanged(ssPostInstall)` 把 HKCU `...\Uninstall\{AppId}_is1` 的 `UninstallString` 与 `QuietUninstallString` 同值写为 `"...unins000.exe" /SILENT /NOSTYLE`。`/SILENT` 的官方语义正好压掉「确认要完全移除」与「已顺利移除」两个弹窗、保留进度窗体；每次重装钩子重跑，Inno 重写注册表后标记自动续上。「设置→应用」优先读 `QuietUninstallString`，故两值同写。
- **/NOSTYLE 兼作标记**：官方惰性开关（本脚本无自定义样式，零副作用）；命令行含它＝ARP 向导模式。选它而非自造开关，是因为官方文档不保证卸载器容忍未知参数，而 ARP 卸载报错是灾难级回归。
- **三段流**：向导首页（`InitializeUninstall`，标题「IMAP Backup GUI 卸载向导」，**通用化正文**——不写死「运行日志」，日后加新选项不用改正文；复选框「同时删除运行日志（含服务器地址与账号名，不含密码）」默认勾选；「卸载(U)」「取消(C)」，取消/关窗/Esc＝中止整个卸载）→ 官方进度窗（零改动）→ 完成对话框（usPostUninstall 删完日志后，「IMAP Backup GUI 已从您的计算机中移除。」＋「完成(F)」，仅 ARP 模式弹出）。决策仍在 usPostUninstall 读取；进度中途取消＝日志保留（既有行为）。
- **双路径行为表**：控制面板/设置→应用＝向导三段、无原生弹窗；直跑 `unins000.exe`＝非静默，向导首页后仍跟原生确认＋完成弹窗（罕见路径，接受并记录）；手动 `/SILENT` 无标记（自动化）＝全程无 UI、默认删日志——真静默语义不变，这正是「标记必须命令行可判别」的由来。
- 首页顺序前提：`InitializeUninstall` 位于原生确认弹窗**之前**、任何删除之前（用户真机截图证实；早先「确认弹窗在最前」的判断是误诊）。

## Considered Options

- **页脚复选框 / 两段式**：分别败于「来不及交互」与「双确认＋观感割裂」，见上。否决。
- **UninstallString 只加 /SILENT 不加标记**：无法区分「ARP 静默」与「自动化静默」，要么自动化被弹窗打断，要么 ARP 路径没有 UI。/NOSTYLE 标记是两个都要的唯一解。
- **自造未知开关（如 /UNWIZARD）当标记**：卸载器对未知参数的容忍度无官方契约，风险不对称。否决。
- **侧边品牌图（NSIS 欢迎页式竖图）／向导化进度页**：用户明确砍掉，观感诉求以后再议。
- **（接受的代价）**① 完成对话框叠在进度窗之上（usPostUninstall 时进度窗体尚未关闭）；② 直跑 exe 路径双重询问；③ 注册表改写是 Inno 无契约的行为缝隙——若未来改变 UninstallString 写入时机或键名，钩子需跟着调（键名与 AppId 逐字绑死已在 [Code] 注释声明）。

## Consequences

- **真机验收**：先重装新包（钩子与新卸载器才就位），再走 ARP 路径验证向导三段（默认删／不勾留／取消不卸／设置→应用一致）、直跑路径老行为、手动 /SILENT 无 UI。
- **文档同步**：CONTEXT.md「卸载程序」、README 安装程序段、AGENTS.md 日志条目；「设置→应用＝静默无窗体」的旧断言作废（改写后它也走向导）。
- 复选框实际删除应用数据目录 `%LOCALAPPDATA%\imapbackup-gui\` 下的明确用户侧数据：运行日志与界面设置分别由各自复选框控制；目录新增内容时必须同步改文案或收窄删除范围。用户备份目录始终不在卸载范围内。
- 版本号未动（1.6.0）；与既有改动一起等 1.6.0 收官统一 push、打 tag。
